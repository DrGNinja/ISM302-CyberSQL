Controlled SQL Injection Defense Simulation

This sandbox teaches why concatenating untrusted input into SQL is unsafe and why parameters are the preferred defense. It does not connect to an external system.

Vulnerable pattern:
SELECT user_id, username FROM users\nWHERE username = '" + userInput + "';
Enter a synthetic username and compare the two designs.
Secure SQLite pattern:
SELECT user_id, username FROM users WHERE username = ?;
// bind user input as the parameter value

Learning goal: distinguish SQL code from data. Parameterization keeps the SQL statement structure fixed while input is bound as a value.
